# 에이전트 띄우기 (요청은 pane 에서)

대상: $ARGUMENTS

권장 방식(CLAUDE.md 3단계 "프롬프트 없이 pane 을 열고 그 안에서 작업을 지시한다")을 한 번에 한다. **헤르메스는 코드를 고치지 않는다.** 띄우는 데까지만 하고, 요청은 사용자가 pane 에서 쓴다.

## 절차

### 1. 대상을 정한다
- 첫 인자 = 에이전트 이름(`.claude/agents/<이름>.md`). 없거나 틀리면 에이전트 목록을 보여 주고 묻는다
- 담당 레포·앱은 `hermes.config.json` 에서 찾는다(bznav 앱 에이전트는 `bznav:<앱>`, `bznav-packages-fe` 는 작업할 앱을 묻는다)
- 둘째 인자 = 브랜치 이름. 티켓이면 `feature/<티켓>`(`/branch` 규칙). **없으면 묻는다** — 임의로 짓지 않는다
- `reviewer` 는 이 스킬로 띄우지 않는다(리뷰할 계획서가 있어야 한다 → `/review`)

### 2. 브랜치 상태를 보고하고 멈춘다
```bash
git -C repos/<레포> status --short --branch
scripts/new-branch.sh <브랜치> <대상> --dry-run
```
- 메인 체크아웃의 브랜치·미커밋 변경, 만들 워크트리 경로·base(`prBase`)·SHA 를 한 표로 보고한다
- **여기서 멈추고 확인을 받는다.** 같은 이름 브랜치가 이미 있으면 이어서 쓸지 새 이름을 쓸지 묻는다

### 3. 확인을 받으면 한 번에 띄운다
```bash
scripts/new-branch.sh <브랜치> <대상>                                  # 워크트리
scripts/delegate.sh <에이전트> --cwd <워크트리> --plan new "<에이전트> 작업 (pane 에서 지시)"
```
- 경량 계획서(`plans/task/…`)는 **빈 지시**로 만들어진다. 에이전트는 첫 요청을 받으면 계획서 제목과 `## 지시` 를 그 요청으로 채운다(delegate.sh 가 지시문 맨 앞에 넣는다)
- 프롬프트를 넘기지 않는다. 에이전트는 브랜치 상태를 한 줄 보고하고 기다린다
- 현황판(`/board`)에 계획서 카드가 **진행 중**으로 뜨고 `🤖 <에이전트>` 배지가 붙는다

### 4. 사용자에게 알린다
- pane id · workspace · 워크트리 · 브랜치 · 계획서 경로를 한 줄씩
- "그 pane 에서 요청을 쓰면 된다. 끝나면 계획서가 ready_for_review 가 되고 현황판 리뷰 칸으로 간다" 한 줄

## 주의
- 요청이 여러 레포·API·구조 변경으로 커지면 에이전트가 멈추고 알린다 → 헤르메스가 정식 계획서(`/feature`)로 옮긴다
- 커밋·PR 은 사용자가 정한다
