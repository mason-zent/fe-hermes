# 버그 수정

보고된 버그: $ARGUMENTS

## 절차

### 1단계: 원인 분석
1. 라우팅 기준으로 의심 서비스를 정하고, Explore 에이전트로 관련 로직을 추적한다
2. 원인이 프론트인지, API 응답인지, 공유 패키지인지 판별한다. 프론트 밖이면 사용자에게 알린다

### 2단계: 계획서 작성 (= 작업 카드)
- `plans/bugfix/YYYYMMDD-제목.md` + `.html`
- **개요 다음에 Checkpoint 블록**(Status / Work ref / Progress / Next / Blocked / Validation / Decisions)
- 원인 분석 결과, 수정 방안, 영향 범위(사이드 이펙트), 작업 배분표
- 사용자 승인 요청. **사용자가 "바로 고쳐"라고 명시하면 계획서 없이 디스패치 가능** (보고에 그 사실 명시)

### 3단계: 작업 브랜치 → 디스패치
1. **`/branch fix/<설명> <대상...>` 으로 작업 브랜치를 먼저 만든다.** 미커밋 변경으로 건너뛴 레포에는 디스패치하지 않는다. 브랜치와 base SHA 는 Checkpoint 의 `Work ref` 에 적는다
2. `scripts/delegate.sh <에이전트>` 로 pane 을 열고 그 안에서 지시한다. 같은 버그가 여러 서비스에 있으면 pane 을 여러 개 연다
3. 긴급 수정으로 계획서를 건너뛴 경우에도 **브랜치는 만든다.** 운영 브랜치에서 고치지 않는다

### 4단계: 검증
- `reviewer`로 수정 코드 검토 (회귀 위험 중심)

### 5단계: 보고
- 원인, 수정 내용, 영향 범위, 검증 결과
