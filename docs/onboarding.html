헤르메스 시작 가이드

헤르메스는 프론트엔드 레포 여러 개를 한 곳에서 다루는 Claude Code 워크스페이스입니다. 이 폴더에서 claude 를 켜면 팀 리드 헤르메스가 되어, 요청을 받아 어느 레포 일인지 고르고 계획서를 쓴 뒤 담당 FE 에이전트에게 맡기고 리뷰까지 받아 보고합니다.

작업하면서 알게 된 레포 함정은 학습해서 다음 작업에 씁니다. 이 문서는 받아서 쓰기 시작할 때까지만 다룹니다.

Nous Research 의 오픈소스 Hermes Agent 와는 이름만 같은 다른 것입니다. 따로 설치하지 않습니다 — Claude Code 위에 우리가 만든 규칙·스크립트 묶음입니다.

01준비물

아래 도구가 필요합니다. 없는 것만 먼저 설치하세요.

도구쓰는 곳없으면
Claude Code 필수헤르메스·에이전트 본체 (claude)동작하지 않음
git · python3 필수셋업·훅·스크립트동작하지 않음
Node + nvm 필수검증·현황판·QA. 레포마다 .nvmrc 버전이 다릅니다검증이 경고·실패
pnpm 필수레포 설치·빌드검증·빌드 불가
gh 필수push·draft PR, 현황판의 PR 머지 감지. gh auth login 까지PR 을 못 올림
herdr 권장에이전트를 옆 pane 에 띄워 일하는 모습을 보여 줍니다pane 대신 "직접 실행하세요" 안내만 나옴

권한과 로컬 파일

  • 맡을 레포들의 GitHub 접근 권한
  • GitHub Packages 읽기 토큰(PAT, read:packages). bznav-web·케어 콘솔 등이 @zenterprise-inc/* 패키지를 받을 때 필요합니다. 레포 .npmrc 가 아니라 ~/.npmrc 에 넣습니다
  • 레포마다 .env. 레포 안내대로 만듭니다(일부는 pnpm gen:env, AWS 자격 필요). 작업 워크트리를 만들 때 메인 체크아웃의 .env* 가 자동으로 복사됩니다
토큰 값은 어디에도 붙여 넣지 마세요. 대화창, 슬랙, 계획서, 커밋 모두 해당합니다.

02설치

대략 10분. 레포를 이미 받아 두었다면 더 짧습니다.

  1. 레포를 한 폴더에 나란히 받기

    헤르메스는 자기 상위 폴더에 담당 레포들이 나란히 있다고 봅니다. 맡지 않는 레포는 없어도 됩니다. 그 레포 담당 에이전트만 쉬게 됩니다.

    ~/work/
├── hermes/                # 이 레포
├── client-brics-refund/
├── client-brics-hub/
├── client-brics-care/
├── web-op/
├── bznav-web/
├── zent-packages/
└── bznav-rn-app/
    cd ~/work
git clone https://github.com/mason-zent/fe-hermes.git hermes

  2. 헤르메스 켜기

    # herdr 를 쓰면 herdr 터미널 안에서
cd hermes
claude

    첫 화면에서 "현황 알려줘" 라고 해 보세요. 레포별 브랜치와 변경 상태가 나오면 준비가 끝난 겁니다.

    따로 셋업하지 않아도 됩니다. claude 를 켜면 옆 폴더의 담당 레포를 찾아 repos/<레포> 로 알아서 연결하고, 못 찾은 레포가 있으면 헤르메스가 위치를 묻습니다.

    QA 시뮬레이션을 쓸 때만 한 번 scripts/setup.sh 를 돌립니다 — Playwright·Chromium 을 설치하고 도구(node·pnpm·herdr…)도 점검해 줍니다.

환급 콘솔 목록 페이지네이션이 두 번째 페이지에서 비어 보여. 원인 찾아줘

레포 고르기→계획서→승인→작업 브랜치→에이전트 pane→리뷰→보고
  • "케어", "환급" 처럼 운영 콘솔인지 비즈넵 사용자 웹인지 갈리면 헤르메스가 되묻습니다
  • 시작할 때 규모를 한 줄로 알려 줍니다
    • 경량 — 문구 수정, 버그 하나, 조사. 요청이 곧 승인이라 바로 진행합니다

  • 급하면 "바로 고쳐". 정식 대상이어도 경량으로 바로 진행합니다
  • 작업은 별도 워크트리(.worktrees/)에서 하므로 메인 체크아웃의 미커밋 변경은 건드리지 않습니다

05학습 — 헤르메스가 배우는 방법

작업하다 밟은 함정을 다음 작업이 또 밟지 않게, 헤르메스가 배운 것을 서비스별 공책(gotchas.md)에 적어 둡니다. 에이전트는 작업 전에 이 공책을 읽습니다.

작업 중·작업 끝→학습 후보→[학습] 탭에서 고르기→공책에 한 줄→다음 작업이 읽음
궁금한 것답
무엇을 배우나그 레포에서 다음에도 마주칠 코드 함정만. 예) "세나 QA 씬은 실제 요청을 직접 막아야 한다", "zent 패키지로 옮긴 앱엔 레포 안 공통 패키지 수정이 안 들어간다"
배우지 않는 것일하는 스타일·취향("표로 보여 줘" 등)은 공용 공책에 넣지 않습니다. 그건 Claude Code 가 각자 컴퓨터에서 기억합니다(클로드 학습). 근거가 코드·실행 결과가 아니라 "사용자가 그렇게 말했다"뿐이면 학습하지 않습니다
언제 생기나에이전트가 작업을 끝낼 때(PR 미리보기)·사용자가 바로잡을 때·같은 오류가 3번 날 때. PR 미리보기 때는 배우기 검토자(별도 Claude)가 그 작업 대화를 다시 읽고 빠진 것을 보탭니다 — "📚 배우기 검토" pane 이 하나 뜹니다(끝나면 닫아도 됩니다. 한 번에 약 $0.1~0.4, 구독이면 사용량에서)
내가 할 일현황판 [학습] 탭 → 🧭 헤르메스 학습에서 후보를 읽고 [넣기]·[고쳐서 넣기]·[버리기]. 넣은 것은 "학습한 내용"에서 언제든 고치거나 지웁니다. 팀과 나누려면 헤르메스에게 "커밋해줘"
대부분의 작업은 학습할 게 0개입니다. 후보가 적은 게 정상입니다. 기준 전체는 docs/knowledge/common/learning.md

07꼭 지킬 것

비밀값은 출력하지 않습니다.npmrc·.env* 내용, printenv, ps aux 결과를 보여 달라고 하지 마세요. 실수로 노출되면 바로 폐기하고 재발급합니다.
무거운 명령은 한 번에 하나install·build·dev·tsc·test 는 scripts/heavy.sh 로 줄을 섭니다. 에이전트는 알아서 씁니다. 직접 돌릴 때도 앞에 붙이세요. 동시 빌드로 컴퓨터가 멈춘 적이 있습니다.
모든 작업은 계획서 하나에헤르메스와 /call 이 알아서 만듭니다. 계획서(plans/)는 각자 로컬에만 있고, 공유되는 것은 issues/·archive/ 입니다.
담당 범위 밖은 수정하지 않습니다백엔드(server-*), zent-packages/backend 등은 범위 밖입니다.
학습은 [넣기]를 눌러야 들어갑니다학습 후보는 [학습] 탭에서 골라야 공책에 들어갑니다. 취향이 섞인 후보는 [버리기].
헤르메스 자체를 고치면 main 에 커밋·push에이전트나 스킬을 추가했다면 docs/extending.md 의 "같이 갱신할 곳"을 따릅니다.
