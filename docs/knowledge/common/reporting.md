# 팀 공통 보고 규칙

에이전트 완료 보고는 항상 아래 4항목. 헤르메스는 이걸 그대로 취합해 사용자에게 전달한다. 보고 전에 계획서 Checkpoint(Status `ready_for_review`·Progress·Validation)를 갱신한다.

1. **변경 파일 목록** (경로, 레포/앱/레이어별)
2. **구현 요약** — 계획서 항목별 완료 / 미완료 / 다르게 한 것과 이유
3. **검증 결과** — `scripts/verify/<레포>.sh` 출력 표를 그대로 붙인다. 실패는 원문 포함. **실행하지 못한 검증은 "실행 못 함"이라고 적는다** (통과한 것처럼 쓰지 않는다). 커밋했다면 `commit.sh` 가 계획서 `## Commits` 에 적은 SHA 를 함께 적고, push·PR 을 했으면(`ship.sh`) PR 링크를, 안 했으면 안 했음을 밝힌다
4. **남은 위험·확인 필요** — 범위 밖 수정 필요, 추측으로 처리한 부분, 다른 서비스 영향, 후속 작업. 그 자리에서 고치지 않은 것(범위 밖 코드 문제·확인 필요·문서 오류)은 대화에만 남기지 말고 `issues/<YYYYMMDD>-<레포>-<제목>.md` 로 등록하고 경로를 적는다(형식 `issues/README.md`)

보고 다음에 — **코드를 바꾼 요청이면 묻지 않고 바로 리뷰를 띄운다**(자동 리뷰): `scripts/delegate.sh reviewer --cwd <워크트리> --here --plan <계획서>` 로 옆에 reviewer pane. 결론(`- Review result:`)이 나오면 사용자에게 보여 준다. reviewer 보고에 **결정 필요**(선택지가 갈리는 항목)가 있으면 말로 묻지 않고 **결정 콘솔**로 — 같은 계획서에 `## 리뷰 뒤 결정` 절을 적고 `node scripts/plan-html.mjs <계획서> --add <결정.json>` → `scripts/board.sh open <계획서>`. 사용자가 고르고 [이대로 진행] 하면 이 pane 으로 결정이 온다. 단순 수정만 있으면 무엇을 고칠지 묻는다. 조사만 했거나 마지막 리뷰 승인 뒤 바뀐 게 없으면 띄우지 않는다

원칙:
- 불확실한 내용은 "추측입니다", "확실하지 않습니다"라고 명시
- 한국어로 소통, 코드 주석도 한국어. 영어는 코드·파일명·기술 용어만
- 같은 오류 3회 반복, 범위 밖 수정 필요, 규칙 충돌은 진행하지 말고 보고
