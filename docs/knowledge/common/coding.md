# 팀 공통 코드 규칙 (모든 레포)

레포 규칙(`docs/knowledge/<레포>/rules.md`)과 레포 원문 문서가 이 문서보다 우선한다. 여기는 **어느 레포에서도 같은 것**만 적는다.

## 작업 원칙
- **모든 작업은 계획서 하나에 묶이고, `prBase` 에서 딴 작업 브랜치·워크트리에서 한다**(`AGENTS.md` 5절, 절차는 `git.md`)
- **작업 전 Node 버전을 레포 `.nvmrc`에 맞춘다** (`nvm use <버전>`). 버전이 다르면 lint 결과가 달라지고 네이티브 모듈(canvas 등)이 로드되지 않아 테스트가 통째로 실패한다. 검증 스크립트가 불일치를 경고로 표시한다. `.nvmrc` 가 없는 레포(web-op)는 검사가 조용히 생략되므로 `<레포>/rules.md` 를 본다
- 작업 전 기존 코드 패턴을 읽고 **그 패턴을 따른다**. 새 스타일을 들이지 않는다
- 요청 범위 밖의 정리·의존성 업그레이드·파일 이동·공통화·전역 포맷팅 금지
- 포맷은 **작업한 파일만**. 명령·설정은 `<레포>/rules.md` 가 정본이다(레포마다 다르다). 대부분 `pnpm exec prettier --write <파일>` + 레포 `.prettierrc` 이고, Prettier 가 없는 레포(bznav-rn-app)는 주변 스타일에 맞춘다
- 자기 담당 범위(레포·앱·디렉토리) 밖은 수정하지 않는다. 필요하면 헤르메스에 보고
- 생성물(`__generated__/`, Relay 아티팩트 등)은 직접 편집하지 않고 생성 명령으로 만든다. 생성 불가 시 임시 코드 + **보고에 명시**
- 사용자가 명시적으로 요청한 것만 수정한다. 읽기·탐색은 자유

## 단순한 구현
- 현재 요구와 확인된 사용처를 충족하는 가장 단순한 구현을 고른다. 미래의 재사용만을 위해 범용 계층·확장 지점·설정 옵션·prop 을 추가하지 않는다
- 가독성·테스트·책임 분리 또는 기존 레포 패턴을 위한 함수·컴포넌트 분리는 한 곳에서만 써도 허용한다
- 방어 분기는 입력 계약과 실제 실행 경로를 근거로 판단한다. 로딩·에러·빈 상태, 외부 입력 검증, 보안상 필요한 처리는 단순화를 이유로 생략하지 않는다
- 줄 수 자체를 목표로 다시 쓰지 않는다. 현재 작업 범위에서 이해·검증 비용이 줄어드는지로 판단한다

## 변수명 / 가독성
- 1글자 변수명 금지 (반복문 변수 포함). 축약어 지양
- 3항 연산자 중첩 금지. 필요하면 함수로 분리
- 새 코드에서 `any` 금지 → `unknown`으로 받아 narrowing. `as any`·불필요한 non-null assertion 금지
- 이번 변경으로 추가됐거나 미사용이 된 import·변수·함수는 정리한다. 기존 미사용 코드는 정리가 요청 범위에 들어 있을 때만 지운다. 범위 밖에서 발견한 것은 고치지 않고 보고·`issues/` 등록한다(`AGENTS.md` 6절)
- 한글 식별자로 인한 lint 경고는 임의 수정 금지 (도메인 용어일 수 있음)

## React / Next 공통 (웹 레포. RN 앱은 `bznav-rn-app/rules.md`)
- 함수형 컴포넌트, `React.FC` 금지
- 운영 코드에 `console.log`/`console.debug` 금지 (`info/warn/error`는 의미 있는 메시지와 함께)
- `window`·`document`·storage 접근은 클라이언트 컴포넌트나 훅 안에서만
- App Router 앱에서 `'use client'`는 state·effect·핸들러·브라우저 API가 필요한 파일에만
- 로딩·에러·빈 상태를 빠뜨리지 않는다. 널 가드

## 성능
- O(n²) 이상 로직, 2중 이상 반복문은 재검토 대상
- 불필요한 리렌더·과도한 데이터 재요청(SWR/Relay) 확인

## 보안
- `.env*`, 토큰, 키 파일 내용은 출력·커밋하지 않는다
- 서버 전용 값을 클라이언트 공개 접두(`NEXT_PUBLIC_`·`EXPO_PUBLIC_`)로 노출하지 않는다
- 인증 토큰·개인식별정보를 storage에 과다 저장하지 않는다

## 오류 대응
- 같은 오류 3회 반복 시 접근 방식을 전면 재검토하고 헤르메스에 보고
