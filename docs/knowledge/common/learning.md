# 학습 기준 (학습 루프)

에이전트와 배우기 검토자(`scripts/learn-review.mjs` · 역할 `.claude/agents/learn-reviewer.md` — 내 작업의 PR 이 머지되면 돈다)가 **같이 읽는 기준**이다. 작업에서 알게 된 것을 각 공책(`docs/knowledge/<영역>/gotchas.md`)에 넣을지 판단하고, 넣을 거면 어떻게 적을지 정한다. 흐름은 `AGENTS.md` 6절 "📚 배운 것".

## 1. 무엇을 학습하나 — 아래를 모두 만족할 때만

- **다시 마주친다** — 그 레포에서 평범한 다음 FE 작업(화면·기능·버그 수정)을 하다가 또 만날 가능성이 높다
- **모르면 실제로 잘못된다** — 잘못 고치거나, 사고(실제 요청이 나감·데이터가 바뀜)를 내거나, 시간을 크게 버린다. "모르면 무엇이 잘못되나"를 구체적으로 한 줄 쓸 수 있어야 한다. 못 쓰면 학습하지 않는다
- **코드만 봐서는 바로 알기 어렵다** — 여러 파일·설정·외부 동작이 얽혀 있거나, 문서와 코드가 다르다

**대부분의 작업은 학습할 게 0개다. 그게 정상이다.** 억지로 만들지 않는다. 한 작업에서 많아야 3개.

## 1-1. 코드로 확인되나 — 사실과 취향을 가르는 기준

학습은 **누가 작업해도 똑같이 밟는 코드 사실**만 담는다(공책은 팀이 같이 쓴다). 사람마다 다른 일하는 스타일은 Claude Code 메모리 몫이다. 둘을 "사실인가 취향인가"로 판단하지 않고, **근거가 어디에 있나**로 가른다.

| 근거 종류(`basis`) | 뜻 | 학습하나 |
|---|---|---|
| `code` | 코드·설정·문서에서 확인된다(파일:줄) | ✅ |
| `run` | 실행 결과로 확인됐다(에러 메시지·요청 기록·테스트 결과) | ✅ |
| `user-said` | 사용자가 그렇게 말한 것뿐이다 | ❌ — 취향일 수 있다. 메모리가 맡는다 |

사용자 교정에서 나온 것도 **코드나 실행 결과로 뒷받침될 때만** 학습한다. 사용자 말만 있으면 학습하지 않는다 — 검토자 답에서 `basis: user-said` 는 스크립트가 기계적으로 버린다.

**헷갈리는 예**

| 후보 | 근거 | 판단 |
|---|---|---|
| 세나 QA 씬은 실제 요청을 씬에서 직접 막아야 한다 | `code` — QA 러너 안전장치가 GraphQL mutation 만 막는다 | ✅ 학습 |
| 패키지에 새 import 경로를 열면 lint 허용 목록도 고친다 | `run` — 소비 앱에서 lint 에러가 났다 | ✅ 학습 |
| 이 레포 날짜는 `formatKst` 유틸로 바꾼다 | `code` — 다른 방식이 섞이면 시간대가 틀리는 줄이 있다 | ✅ 학습 |
| 이 레포 날짜는 `formatKst` 유틸로 바꾼다 | `user-said` — "그거 말고 formatKst 써" 만 있고 코드상 이유를 못 찾았다 | ❌ 취향일 수 있다 |
| 결정은 표로 보여 줘 · pane 에 띄워 줘 · 요청한 것만 해 | `user-said` | ❌ 일하는 스타일 — 메모리 |
| 커밋 메시지는 한국어로 | `code` — 레포 규칙 문서(`rules.md`)에 이미 있다 | ❌ 이미 있음 — 새로 넣지 않는다 |
| 질문 직후 "새 채팅"을 누르면 질문이 빈 채로 전송된다 | `run` — 요청 기록 | ❌ 앱 버그 — 고치면 사라진다. 이슈로 |
| 옛 lint 설정의 내부 경로 금지 규칙은 사실상 꺼져 있다 | `run` | ❌ 새 설정으로 옮기는 중에만 맞는다 |

## 2. 학습하지 않는 것

- **이번 작업에서 이미 코드로 고친 버그·누락** — 이제 코드가 막아 주니 기억할 필요가 없다
- **아직 안 고친 버그·설계 문제** — "질문이 빈 채로 전송된다", "웹에서 이 버튼이 반응이 없다"처럼 **고치면 사라지는 것**은 배울 게 아니라 고칠 것이다. 이슈(`issues/`, `kind: code`)로 남긴다. 함정은 "코드가 원래 그렇게 생겨서 앞으로도 조심해야 하는 것"이다
- **옮기는 중에만 맞는 것** — 라이브러리·설정 전환처럼 끝나면 의미가 없어지는 사실. 전환이 끝나면 낡은 줄이 된다
- **한 번 있었던 장애·문의·조사 결과** — 재현·원인 규명 이야기
- **원인이 FE 레포 밖**인 것 — 서버·인프라·CDN·외부 서비스
- **이번 작업에서 만든 도구·스크립트 자체의 구현 세부**
- **그 작업의 요구사항·결정·진행 경과**, 일반 상식·일반 프레임워크 지식
- **"X 는 안 된다" 같은 단정** — 그때 환경 탓일 수 있다. 조건을 붙이거나 적지 않는다
- **환경 탓 실패**(네트워크·권한·로컬 설정·**Node·pnpm 버전**·설치 상태), **해결 못 한 실패를 정답처럼** 적기
- **사용자 선호·일하는 스타일**(말투·보고 형식·작업 방식) — Claude Code 메모리가 맡는다(`AGENTS.md` 2.5). 근거가 사용자 말뿐인 것은 모두 여기로 본다(1-1)

## 3. 어떻게 적나 — 있는 그대로 옮기지 말고 쉽게

학습 후보는 이슈(`issues/<날짜>-<영역>-learn-<이름>.md`)로 올라가 현황판 **[학습] 탭**에 뜬다. 사용자가 읽고 [넣기]를 누를 수 있게, **그 작업을 모르는 사람이 봐도 알 수 있게** 쓴다.

| 칸 | 쓰는 법 |
|---|---|
| 제목 | 무엇을 학습했는지 쉬운 한 줄. 파일명·함수명 대신 "무슨 일이 생기나"로 |
| `## 무엇을 배웠나` | 2~3문장. 배경부터 짧게 → 무엇이 함정인지. 전문 용어·약어는 풀어서. 대화·로그 문장을 그대로 붙이지 않는다 |
| `## 왜 중요한가` | 모르면 다음 작업에서 무엇이 잘못되나 한 줄 |
| `## 공책에 넣을 문장` | 공책(gotchas)에 실제로 들어갈 한 줄 — **규칙 + 이유 한 마디**. 에이전트가 작업 전에 읽고 바로 행동할 수 있게. PR 번호·날짜·작업 이야기는 빼고 필요하면 파일 경로 |
| `## 어디서 배웠나` | 어느 작업(계획서)에서, 무엇을 보고(파일:줄·확인한 사실 한 줄). 비밀값·긴 인용 금지 |
| front matter `basis:` | 근거 종류 `code` · `run`(1-1). `user-said` 면 후보를 올리지 않는다 |

**예** — 좋은 것 / 나쁜 것

> 제목: 세나 웹 QA 씬은 실제 요청을 직접 막아야 한다
> 무엇을 배웠나: QA 시뮬레이션은 화면을 실제 브라우저로 눌러 보는데, 환급 웹에서는 러너가 데이터를 바꾸는 요청을 알아서 막아 준다. 세나 웹은 요청 방식이 달라(REST) 러너가 막지 못한다. 그래서 씬마다 직접 가짜 응답(mock)을 걸어 둬야 한다.
> 왜 중요한가: 모르고 씬을 짜면 dev 서버에 실제 질문·설문·탈퇴 요청이 나가 테스트 계정 상태가 바뀐다.
> 공책에 넣을 문장: 세나 흐름 씬은 질문·피드백·이름 바꾸기·설문·탈퇴 REST 요청을 씬 안에서 mock 으로 막는다 — QA 러너의 안전장치는 GraphQL mutation 만 막는다.

> ❌ "minimatch 3.1.5 는 맨 앞 `!` 를 패턴 전체 부정으로 읽어 `'!(@repo)/**/*'` 가 …" — 원문을 옮겨 적어 처음 보는 사람이 무슨 일인지 모른다

## 4. 중복이면 새로 쓰지 않는다

먼저 그 공책과 열린 학습 후보를 찾아본다. 이미 있으면 새 줄이 아니라 **기존 줄을 더 정확하게 고친다** — 후보 front matter 에 `strengthen: <공책에 적힌 그 줄 그대로>`(앞의 `- `·`<!-- learn:… -->` 표시는 빼도 된다). 정확히 같은 줄만 고치고, 못 찾으면 [넣기]가 거부한다. 그 줄이 이미 학습으로 들어온 줄이면 새 학습이 아니라 **그 학습 기록에 이어 붙는다**. 같은 대상의 열린 후보가 있으면 거기에 덧붙인다.

## 5. 반복 절차는 스킬 후보

같은 절차를 손으로 다시 하게 되면 `target: skill:<이름>` 후보에 "반복 +1"을 덧붙인다. 2회 이상이면 "🛠 스킬로 만들까요?" — 스킬은 사용자가 고르면 헤르메스가 만든다(`docs/extending.md` "학습으로 스킬 만들기").

## 6. 저장·승인

- 에이전트·검토자는 **공책을 직접 고치지 않는다.** 후보만 올린다
- 공책은 **각 영역의 `gotchas.md` 하나**다(모든 작업이 다 읽는 파일). patterns·workflows 에는 넣지 않는다. `target` 의 `#절` 은 같은 대상 후보를 합칠 때만 쓰고, 넣을 때는 늘 공책 끝 `## 학습` 절로 들어간다
- 사용자가 [학습] 탭에서 **[넣기]·[고쳐서 넣기]·[버리기]** 를 고른다. 넣으면 공책 끝 `## 학습` 절에 한 줄(`<!-- learn:<id> -->` 표시), 쉬운 설명 기록은 `docs/knowledge/learned/<id>.md` 에 남는다
- 학습한 내용은 [학습] 탭에서 언제든 **수정·삭제**한다(삭제는 휴지통 — 되살릴 수 있다)
- 기록에는 **넣은 사람**(`approved_by` — 그 컴퓨터의 git 사용자 이름)이 남고, [학습] 탭 "학습한 내용" 오른쪽에 보인다
- 팀 공유(git 커밋)는 사용자가 "커밋해줘" 할 때 모아서
- 넣기·버리기 수를 센다 — 2~3주 뒤 넣기 비율을 보고 자동 반영 여부를 다시 정한다
